## Implementation / boundaries

- New migration: `20261026000000_add_daily_qualification.sql`; all earlier migrations unchanged.
- Internal SECURITY DEFINER helper + Item/plan triggers extend the existing Business API → RPC transactions. Existing Commands already lock the owned plan first; the helper takes that same lock and filters by plan/user. No callable qualification endpoint or domain-table write grant was added.
- N counts all Initial / Added Later Task or Milestone Daily Items. Only the per-day `completed` result contributes to completion. Calendar Events / schedule-only Tasks are excluded. Pending, incomplete, cancelled and rescheduled Items remain in N; no cancellation/reschedule command is implemented.
- Exact integer comparison decides >=80%, with N>0 and every current Must-do completed. The database generates the display percentage, truncated to two decimal places.
- Persisted counts, qualification and calculation time are updated in the same transaction as execution, Added Later and Commit. Unchanged aggregates preserve timestamps; qualified_at stays stable while qualified and clears on reversal.
- Missing plans and Draft have no official Daily Status. Committed plans (including history) expose stored day results; M2-01's current-user-date / Committed-only execution rules are unchanged.
- Migration initializes existing aggregates solely from their own Daily Items, without touching Tasks or snapshot Items. For newly observed qualified history, qualified_at is calculation time, not an invented historical achievement time; existing valid qualified timestamps are retained.
- GET Today and shared types carry persisted counters/percentage/flags/times. Desktop only displays them and refetches after Commands; it never decides qualification. Existing Figma node 13:2's right rail, numeric hierarchy, five-segment progress and qualification message are reused. Reward/Wish row is intentionally absent because those features remain unimplemented.
- No Reward Event, Wish, Project, Reschedule, new dependency, or other ticket status change.
