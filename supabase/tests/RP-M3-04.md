```sql
begin read only;
set local statement_timeout = '10s';
set local lock_timeout = '3s';

with expected(signature, client_rpc) as (
  values ('start_wish(uuid)', true), ('switch_wish(uuid)', true),
    ('lock_wish_reward_user(uuid)', false), ('assert_wish_reward_history(uuid)', false),
    ('prepare_wish_rewards(uuid)', false), ('apply_wish_pending(uuid,uuid)', false),
    ('wish_lifecycle_json(uuid,uuid)', false), ('change_current_wish(uuid,boolean)', false),
    ('sync_daily_reward_event(uuid,uuid)', false)
), functions as (
  select e.signature, e.client_rpc, p.oid is not null as present, p.prosecdef as security_definer,
    p.proconfig as config,
    exists (select 1 from pg_catalog.aclexplode(coalesce(p.proacl, pg_catalog.acldefault('f', p.proowner))) a
      where a.grantee = 0 and a.privilege_type = 'EXECUTE') as public_execute,
    pg_catalog.has_function_privilege('anon', p.oid, 'EXECUTE') as anon_execute,
    pg_catalog.has_function_privilege('authenticated', p.oid, 'EXECUTE') as authenticated_execute,
    pg_catalog.has_function_privilege('service_role', p.oid, 'EXECUTE') as service_execute
  from expected e
  left join pg_catalog.pg_proc p on p.oid = pg_catalog.to_regprocedure('public.' || e.signature)
), tables as (
  select c.oid, c.relname, c.relrowsecurity,
    pg_catalog.has_table_privilege('anon', c.oid, 'SELECT,INSERT,UPDATE,DELETE') as anon_access,
    pg_catalog.has_table_privilege('authenticated', c.oid, 'SELECT') as auth_select,
    pg_catalog.has_table_privilege('authenticated', c.oid, 'INSERT,UPDATE,DELETE,TRUNCATE') as auth_write,
    pg_catalog.has_table_privilege('service_role', c.oid, 'SELECT') as service_select,
    exists (select 1 from pg_catalog.aclexplode(coalesce(c.relacl, pg_catalog.acldefault('r', c.relowner))) a
      where a.grantee = 0) as public_grant
  from pg_catalog.pg_class c join pg_catalog.pg_namespace n on n.oid = c.relnamespace
  where n.nspname = 'public' and c.relkind = 'r'
    and c.relname in ('wish_reward_state','wishes','reward_allocations')
)
select 'functions' as check_name, jsonb_agg(to_jsonb(f) order by f.signature) as evidence from functions f
union all
select 'table_rls_acl', jsonb_agg(to_jsonb(t) - 'oid' order by t.relname) from tables t
union all
select 'columns', jsonb_agg(jsonb_build_array(a.table_name, a.column_name, a.data_type, a.is_nullable, a.column_default)
  order by a.table_name, a.ordinal_position)
from information_schema.columns a
where a.table_schema = 'public' and (a.table_name = 'wish_reward_state'
  or (a.table_name = 'reward_allocations' and a.column_name in ('source_revision','entry_key')))
union all

from pg_catalog.pg_constraint c join tables t on c.conrelid = t.oid
where t.relname = 'wish_reward_state' or c.conname in ('reward_allocations_operation_check',
  'reward_allocations_operation_key','reward_allocations_reward_owner_fk','reward_allocations_wish_owner_fk')
union all
select 'policies', jsonb_agg(jsonb_build_array(p.tablename,p.policyname,p.roles,p.cmd,p.qual,p.with_check)
  order by p.tablename,p.policyname)
from pg_catalog.pg_policies p join tables t on t.relname = p.tablename where p.schemaname = 'public'
union all
select 'one_unlocking_index', jsonb_agg(jsonb_build_array(i.indisunique,i.indisvalid,pg_catalog.pg_get_indexdef(i.indexrelid)))
```

## Command contract

`POST /api/commands/wish/start` / `/switch`, strict `{wishId: UUID}`. No client
owner/progress/amount/status/timestamp fields. The verified user JWT invokes
start_wish/switch_wish; auth.uid determines owner. Missing/foreign targets both
404 WISH_NOT_FOUND. Clients still have no direct Wish/Allocation write grants.

- No current: Start starts/resumes Wishlist; Switch is 409 WISH_NOT_UNLOCKING.
- Other current: Start is 409 WISH_ALREADY_UNLOCKING; Switch atomically returns
  old Wish to Wishlist and starts/resumes target. Old progress is not transferred.
- Current target: 200 changed=false, effects=[], no consumption, initialization
  or timestamps changed. Invalid/stale reversal history is rejected, not repaired
  during a promise of no-op.
- Unlocked/Redeemed target: 409 WISH_START_NOT_ALLOWED, including a retry after
  a first Start that immediately unlocked. No durable replay receipt.
- started_at is first start; resume preserves it. Unlock is automatic at target;
  overflow stays Pending and currentWishId becomes NULL. No next Wish auto-start.

Response data: changed, wish (id/title/target/status/coverPath/lifecycle times/
updatedAt/progress), previousWish or NULL, currentWishId or NULL, pendingApplied
and pendingRemaining. The latter is a decimal integer STRING to avoid truncating
owner-wide bigint sums in JavaScript. Per-Wish progress/applied stay integer
and <= target. API parses the transaction envelope and strips unknown/private
fields; it does not invent state/effects. Create Wish's Wishlist/null-lifecycle
contract remains separate and unchanged.

Actual effects: wish_started OR wish_resumed; wish_switched when applicable;
pending_progress_applied and wish_progress_changed on consumption; wish_unlocked
when that transaction reaches target. Historical paused-Wish correction can also
produce wish_progress_changed. No-op has no effects. Existing Daily API/effects
contracts remain unchanged; later Wish query/UI/effect integration is not added.

Errors: 400 INVALID_REQUEST / INVALID_WISH_START_REQUEST, 401 UNAUTHORIZED /
AUTHENTICATION_REQUIRED, 404 WISH_NOT_FOUND, 409 state conflicts or
REWARD_ALLOCATION_INCONSISTENT, 503 WISH_START_UNAVAILABLE for missing contract
or explicit transaction-unavailable codes. Unexpected errors are generic 500.
Transport failures never prove rollback and are never automatically retried.

## Ledger / narrowly necessary metadata

- Existing Event ID, amount, created_at and Daily qualification/history rules
  remain authoritative and unchanged. Only Daily +1 remains a permitted source.
- Historical Active unallocated gaps lazily become Pending under the owner lock,
  then the selected target consumes them. Existing legal signed allocations are
  adopted without deleting or normalizing them. Reversed gaps mint nothing.
- Nonnegative net per Event/target, source total <= original amount and Wish
  total <= target are checked before changes. Initialized Active deficits reject,
  not silently refill. Invalid history aborts every command write.
- Once initialized: Active net Pending + all Wish contributions = Event.amount.
  Reversed Pending/nonterminal contributions net=0; terminal contributions stay.
  No status-based blanket exclusion of reversed Events from Wish progress.
- Reversal appends negative corrections for all nonterminal targets, including
  paused Wishlist. Terminal contributions never relock or become spendable.
  Reactivation restores amount minus retained terminal contributions, routing
  to the then-current Wish or Pending. No cross-Event debt or negative Pending.
- Transfers append same-Event Pending -x / Wish +x. Consumption is FIFO by Event
  created_at then id; row-lock order is independently deterministic by UUID.
  Target cap, overflow and unlock are one transaction.

New internal state: wish_reward_state, one PK row per Event, owner-aware FK,
initialized/last_status/revision. PK prevents a second initial marker; initialized
distinguishes legal historical gaps from corrupt processed deficits; last_status
and revision distinguish reversal/reactivation cycles. All changes are atomic.
Authenticated/anon have no marker access; service_role has inspection SELECT,
and internal processing functions are revoked from all API roles.

Two nullable Allocation metadata columns preserve legacy rows. The unique
(reward_event_id, source_revision, entry_key) prevents a repeated credit, a
repeated correction for one target, or a repeated leg of the same transfer within
one source cycle. Metadata must be both present or both absent. Marker revision
and these keys explain duplicate prevention without request receipts, wallets
or a generic transaction framework. A failed pair or marker update rolls back.

## Locks / migration boundary

Existing execution paths were inspected: Task execution holds settings -> Plan ->
Task -> Item; Commit has its existing Plan/Items/Task/Planning locks; Added Later
holds Plan/Task/Planning before its Item-trigger chain. Qualification/reward
triggers run within those transactions. No pre-existing prefix is reordered.

New common suffix: profile FOR NO KEY UPDATE -> all existing owned Events by id
-> processing rows by Event id -> all owned Wishes by id -> Allocations by id.
The profile mutex also exists when there is no current Wish or source. It is
compatible with FK KEY SHARE. Daily acquires it before INSERT/UPDATE of Event;
Wish commands never request Daily Plan/Task/Item locks. Sources are prelocked in
Daily before changing its own Event; a newly inserted Event is not visible to
another owner-mutex writer until commit. No late Event-row trigger acquires the
user mutex in reverse order.

Cover association keeps Wish -> Storage object order; it never requests profile
or Event locks, and lifecycle never requests Storage locks. Column-specific
UPDATEs preserve cover_path and metadata while cover preserves lifecycle fields.
No guarantee covers concurrent privileged edits bypassing the domain commands.

The migration uses transaction-local 10s lock / 60s statement limits and a brief
daily_plans ACCESS EXCLUSIVE lock to drain old Daily executions before replacing
sync_daily_reward_event. There is NO data backfill. DDL function replacement,
new metadata/constraints, empty search_path and least-privilege grants install
atomically. Review/deployment must not reuse the old M3-03 exactly-one-pending
preflight, which names a different migration. No new preflight tool is added.
